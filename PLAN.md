# HOTARU — Plan

The plan for building the game described in [`SPEC.md`](SPEC.md). The spec is the source
of truth for *what*. This file covers *how*, *in what order*, and *what could go wrong*.
Non-obvious choices are logged in [`DECISIONS.md`](DECISIONS.md). Progress is tracked
in the status table in [`README.md`](README.md).

---

## 1. Agreed ground rules (from the Start Q&A)

| Topic | Decision |
|---|---|
| Hosting | GitHub Pages via an Actions workflow. **You** make the repo public and set *Settings → Pages → Source: GitHub Actions* once. |
| Git flow | One branch per milestone (`m1-foundations`, `m2-terrain`, …) → PR → you review and merge. Pages deploys from `main` after the merge. |
| iPad performance | An in-game **benchmark** (debug panel → "Benchmark"): scripted 60 s flythrough per preset, shows avg / 1 %-low frame time and a copyable result line. You run it on the iPad at each milestone and paste the numbers; I record them in the README. Headless numbers from this container are software-rendered and only used to catch regressions. |
| Scope vs. look | **The look wins.** If the iPad can't hold 60 fps on Medium, the world shrinks (e.g. 6–8 km) or minor regions merge before rendering quality or density drop. World size is one config constant from day one. |
| Look check | No extra checkpoint inside M1; I stop once at the end of M1 with screenshots. |
| Seed | One **fixed curated seed** is the default "New Journey"; custom seeds are an option. Landmarks, views and secrets are tuned and verified on that seed. |

## 2. Tech choices

| Area | Choice | Why |
|---|---|---|
| Language / build | TypeScript (strict), Vite, ES modules, pinned versions | Spec. Fast dev server, hashed assets for the precache manifest. |
| 3D | Three.js (pinned, WebGL2), **custom `ShaderMaterial`s** sharing one GLSL chunk library | Built-in PBR materials fight the banded-light look. Own shaders give full control of ramps, tinted shadows, rim and fake subsurface, and per-material palette hints. Three still gives us scene graph, instancing, shadow maps, loaders-free geometry. |
| Post pipeline | Own small chain of full-screen passes (no `EffectComposer`) over half-float render targets at internal resolution | Few passes, exact order from SPEC §3.12, cheap ping-pong at ~640×360. |
| Palette quantization | Per-frame lookup in a **3D LUT texture** (RGB → nearest + second-nearest palette colour + blend weight, computed in OKLab). LUT rebuilt in a worker when the blended time-of-day palette drifts past a threshold | Exact OKLab nearest-colour per pixel on the GPU with 96 colours is too slow on iPad; a 32³ LUT costs one texture fetch. Palettes change slowly, so rebuilding a few times per in-game hour is enough. |
| Dither | Bayer 4×4 (blue noise option later), strength per pixel from a "surface flatness" hint written to the G-buffer alpha (strong in sky/gradients, weak on textured surfaces) | SPEC §3.4. |
| Pixel stability | Camera position snapped to the texel grid in camera space; sub-pixel remainder applied as an offset in the upscale pass; 1-texel render margin so the offset never shows an edge. Shadow cascades texel-snapped | SPEC §3.2. Rotation-induced shimmer is mitigated by low-frequency textures and alpha-tested foliage. |
| Upscale | Integer nearest-neighbour when it fits, otherwise sharp-bilinear (integer pre-scale + bilinear) | Square, even pixels at 2360×1640 and odd desktop sizes. |
| Many lights | **CPU-built screen tile grid** (e.g. 16 px tiles at internal res → ~40×23 tiles) packed into a data texture; forward shaders loop over the tile's light list, capped per preset (8/16/32). Far lanterns become emissive glow sprites | Internal resolution is tiny, so tiling is cheap on CPU and avoids a compute pass WebGL2 doesn't have. |
| Water | Planar reflection camera at half internal res (max 2 water heights), normal-driven **vertical** distortion to get horizontal streaks, glitter path from a light-aligned sparkle term, depth fade, foam | SPEC §3.8; reference images. |
| UI | Separate **2D canvas** at low UI resolution (integer UI scale, auto 3–5 on iPad), upscaled with `image-rendering: pixelated`; small retained-mode toolkit; fonts and icons defined as pixel maps in TS data files | Crisp pixel UI, no DOM widgets, fully offline. |
| Fonts | Original bitmap fonts drawn as string pixel maps: body (~6×10, Latin + ä ö ü ß), heading (brush feel), tiny numeric | SPEC §9.4. |
| Workers | Terrain gen/meshing, scatter, LUT building, pathfinding. Comlink-free tiny typed message layer, transferable buffers | No main-thread stalls. |
| RNG / noise | sfc32 / mulberry32 seeded streams per subsystem; local OpenSimplex2 2D/3D | Same seed → same world; tests hash chunk output. |
| PWA | `vite-plugin-pwa` (Workbox, `generateSW`, all build files precached, cache-first) + hand-written manifest and iOS meta tags; icons and launch images **generated by a Node script** (pixel lantern) | Proven precache generation; Workbox runtime gets bundled, so still zero network at runtime. |
| Storage | Small hand-written IndexedDB wrapper for saves and on-device caches (generated textures/impostors); localStorage for settings only; `navigator.storage.persist()` | SPEC §2, §27. |
| Audio | Web Audio only, procedural synthesis (M13), but the audio-unlock-on-first-touch plumbing exists from M1 | iOS gesture requirement. |
| Tests | Vitest (unit), Playwright (screenshots, offline boot, touch emulation); fixed seed/time/weather/camera via URL params, e.g. `?seed=…&t=21.5&shot=dock-night` | SPEC §29. |
| Debug | Debug panel from M1 (`` ` `` / 3-finger tap): FPS, draw calls, tris, time slider, weather/season pickers (stubs until their milestone), pass toggles, seed, free-fly cam, benchmark | SPEC §2. |

Content (plants, animals, NPCs, dialogue, secrets, items, festivals, palettes, fonts, icons)
lives in `src/**/data/*.ts`, separate from logic. Files stay under ~600 lines.

### M1 — Foundations & THE LOOK prototype
1. Scaffold: Vite + TS strict + Three + Vitest + Playwright + ESLint/Prettier, folder
   structure from SPEC §2, event bus, world clock, seeded RNG, noise (+ tests).
2. Render core: low-res HDR target, resize/integer-scale logic, upscale pass with
   sub-pixel offset, camera snapping.
3. Shader library: banded Lambert ramp, hemispheric ambient, tinted shadows (1–2
   stabilised cascades), rim light, backlit subsurface, emissive, tiled point lights.
4. Post chain: fog/aerial → bloom (low-res, lantern halos) → tonemap → grade
   (lift/gamma/gain + split tone per time) → palette LUT quantize + Bayer dither →
   outlines (depth/normal, darker-shade) → vignette. Every pass toggleable.
5. Palettes: night and golden-hour palettes (48–96 colours) from SPEC §4, blended by
   time; LUT worker.
6. Test scene "Tomoshibi dock": small lake with planar reflections, glitter path and
   streaks, wooden pier and posts, boathouse with lit windows, a string of swaying
   lanterns with halo sprites, moored rowboat bobbing (plus one rowing with a wake for
   the dusk shot), maple and pine trees with leaf-cluster cards and wind, grass cards,
   reeds, falling leaves, fireflies, simple gradient sky with moon/stars and a layered
   mountain backdrop with aerial perspective.
7. Minimal free-look/walk camera (keyboard+mouse and touch drag) — the full controller
   is M3.
8. Pixel UI foundation: UI canvas + integer UI scale, body + heading bitmap fonts,
   9-slice washi/lacquer panels, pixel title screen (logo, wooden plaque menu,
   fireflies, drifting camera over the dock scene), `ui-gallery` debug page.
9. Debug panel + FPS counter + benchmark scaffold.
10. PWA: manifest, generated icon set + apple-touch-icon + iPad launch images, iOS
    meta tags, service worker precache, update toast, gesture/zoom/selection
    prevention, safe areas, visibility pause, WebGL context-loss recovery,
    `storage.persist()`.
11. GitHub Pages workflow (correct Vite `base`), README install instructions.
12. Playwright: screenshots (dock night ≈ reference 1, lake dusk ≈ reference 2, title
    screen, ui-gallery) at 2360×1640, pixel-stability check (camera moves sub-texel →
    image differs only by shift), offline boot test.

## 4. Risks & mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| **The look doesn't match the references** | Core of the project | Spend M1 almost entirely on the pipeline; compare screenshots side-by-side with the references; every post pass individually toggleable and tunable in the debug panel; palette and ramp values in data files. |
| Shimmer / crawling pixels while turning | Breaks the "painting" feel | Camera position snapping + sub-pixel offset; low-frequency textures; alpha-tested foliage with dithered LOD fade; automated stability test. Rotation shimmer can't be fully removed in first person — keep it minimal and test on the iPad. |
| Palette quantization banding or "posterised mud" | Ugly gradients | OKLab distance, dither strength per surface, palette sizes 48–96, a "palette strength" mix setting, iterate palettes against the references. |
| iPad Safari GPU/driver limits (half-float targets, shader compile stalls, precision) | Crashes / hitches | Check `EXT_color_buffer_half_float` with an RGBA8 + encoded fallback; compile all shader variants on the loading screen; keep `highp` where needed; test early via your benchmark. |
| iPad memory (tab killed ≈ 1–1.5 GB) | Crashes when streaming a 10 km world | Strict budgets (SPEC §28), pooled buffers, disposal, low-res textures; world size can shrink (agreed). |
| Scale: 10 km world, 22 regions, 100+ secrets, 1500 lines | Very long build across many sessions | Milestones are self-contained and always playable; README table + per-milestone checklists in PRs make each session resumable; content in data files, generated in batches. |
| Performance can't be measured here | Wrong tuning | In-game benchmark you run on the iPad; auto-quality from M14; conservative Medium defaults. |
| Headless Chromium uses software GL | Slow, sometimes different screenshots | Fixed seeds/time/camera, generous timeouts, small set of canonical shots; verify the key ones on real hardware via the Pages build. |
| PWA offline quirks on iOS (SW updates, storage eviction) | Game won't start offline / saves lost | Full precache, cache-first, offline Playwright test each milestone, `storage.persist()`, save export, never force-reload. |
| Original-content rule | Legal/creative | All art, fonts, music, names and text generated or written fresh; nothing copied. |
